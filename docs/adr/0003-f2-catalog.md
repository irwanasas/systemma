# 0003 — F2 catalog decisions

Status: accepted

## Decisions

- `carts` and `cart_items` tables are created in F2 (schema only) because `price_quote(cart_id)` is defined over the cart and is F2's test gate. Cart RPCs come in F3.
- `price_quote` returns every cart line with an `is_orderable` flag instead of raising: false when the product is not active, the batch is not open or belongs to another product, the variant is inactive, the size has no price, or custom size is disabled. The cart page can show unavailable lines; checkout (F3) refuses them.
- Variants are generated by triggers: every color × size gets a variant, active only when the size has a price. Variants are never deleted by price changes (they may be referenced), only deactivated.
- SKU = `SLUG-COLORNAME-SIZE` (color name stripped to letters and digits, uppercased). Normalized color names are unique per product. SKUs do not change when a product is renamed.
- A product has at most one `open` batch (partial unique index), so the catalog's current batch is unambiguous.
- Batch numbers are `max + 1` per product; the default label is `B{n}`. New batches start as `scheduled`; admins open, close and reopen them.
- "Delete product" tries a hard delete; if anything references it (cart items, and orders from F3), it is archived instead.
- `product_images` exists in the schema but has no UI yet (Storage is not part of the local stack or F2 scope).
- Money inputs accept `250.000`, `250000`, or `Rp 250.000`; decimals are rejected. `datetime-local` inputs are read as Asia/Jakarta (UTC+7, no DST).
- Admin forms share one client component, `components/ui/action-form.tsx` (pending state, error, success message, optional confirm).
